# Правила работы команды

## Ветвление (GitHub Flow)

- Основная ветка – `main`. Она всегда стабильна, прямые коммиты в нее запрещены.
- Каждая задача из бэклога выполняется в отдельной ветке от `main`. Имя ветки начинается с номера задачи в Jira:
  - новая функция – `feature/LIB-<номер>-<кратко>`, например `feature/LIB-41-fulltext-index`;
  - исправление ошибки – `bugfix/LIB-<номер>-<кратко>`, например `bugfix/LIB-57-loan-expiry-date`.
- Сообщение коммита начинается с номера задачи: `LIB-41: индексация текста PDF и EPUB`.

## Pull Request

Pull Request создается, когда:

1. модуль собирается без ошибок;
2. для новой логики написаны xUnit-тесты, и они проходят;
3. изменения API внесены в `docs/openapi/library-catalog.yaml`.

Слияние в `main` – после одобрения хотя бы одного коллеги и успешного прохождения автоматических тестов. Ветка после слияния удаляется.

## Code Review

Ревьюер проверяет изменения по чек-листу из [шаблона Pull Request](.github/pull_request_template.md).
